# FinHealifi

Вебзастосунок, який допомагає людині з кількома боргами скласти план їх погашення з найменшою переплатою. Він збирає транзакції користувача, розкладає витрати за категоріями, показує, скільки вільних грошей лишається щомісяця, будує оптимальний план погашення за допомогою MILP і пояснює результат українською через Claude API.

Капстоун-проєкт (MVP) програми Data Science.

## Функціонал

- **Джерела транзакцій:**
  - синхронізація з Monobank API (ручна і щоденна автоматична, лише нові транзакції);
  - імпорт банківських виписок CSV, XLSX і PDF з попереднім переглядом розпізнаних колонок;
  - ручне введення.
- **Очищення даних:** пошук дублікатів між джерелами з урахуванням банку й точності часу; архів видалених рядків з можливістю відновлення.
- **Категоризація:** правила за MCC-кодами й ключовими словами, ручний вибір, власні категорії користувача, ML-класифікатор для нерозпізнаних транзакцій; черга перегляду незрозумілих надходжень (дохід, повернення позики, повернення частки спільної витрати).
- **Борги:**
  - облік кредитних карток і розстрочок;
  - калькулятор доступної суми на основі історичного вільного грошового потоку;
  - план погашення з помісячним розкладом і порівнянням стратегій;
  - ознака того, що збережений план застарів після зміни боргів.
- **Активи й позики:** заощадження, інвестиції та позики, видані іншим людям.
- **AI-радник:** відповідає на запитання за вже порахованими числами. Модель нічого не рахує сама й отримує лише агреговані показники, без описів транзакцій.

## Data Science

| Компонент | Реалізація |
|---|---|
| Оптимізація погашення боргів | MILP (PuLP + CBC): мінімізація сумарних відсотків; бінарні змінні вмикають мінімальний платіж лише поки борг не погашено. Порівняння з евристиками avalanche, snowball і «лише мінімум»; тест перевіряє, що MILP не гірший за евристики |
| Категоризація транзакцій | Ембедінги sentence-transformers + LogisticRegression + SMOTE; спільна модель і персональні моделі з підвищеною вагою власних прикладів |
| Оцінка категоризатора | 5-fold StratifiedGroupKFold з групуванням за нормалізованим описом, бейзлайни (мажоритарний клас, пошук за описом), бутстреп-інтервал macro-F1 (`scripts/analysis/categorizer_eval.py`) |
| Прогнозування | Prophet і прості базові моделі (середнє, медіана, наївна), бектест без витоку майбутнього (`scripts/analysis/forecast_backtest.py`) |
| Правила планування платежу | Бектест правил вибору додаткового платежу з інтервалами Вілсона (`scripts/analysis/planning_rules_backtest.py`) |
| Розбір виписок | Пошук рядка заголовків, зіставлення колонок (нечітка схожість рядків + схожість ембедінгів + перевірка вмісту), перевірка безперервності залишку, розбір PDF-таблиць і PDF-звітів з блоками транзакцій |

**Результати на даних автора:**
- Більшість транзакцій категоризують правила (близько 80 %) і ручний вибір (близько 18 %); ML-класифікатор — запасний рівень.
- На нових описах (групове розбиття) класифікатор має macro-F1 0.23 (95 % інтервал 0.20–0.25). Випадковий split того самого пулу дає 0.79, бо більшість тестових описів уже є в train.
- Prophet у бектесті не перевершив простих базових моделей, тож прогноз у застосунку не показується. Додатковий платіж задає користувач, а калькулятор показує історичний вільний потік.

## Стек

- **Бекенд:** Python 3.12, FastAPI, SQLAlchemy (async) + asyncpg, Alembic, PostgreSQL 15, APScheduler.
- **ML і оптимізація:** scikit-learn, imbalanced-learn, sentence-transformers, Prophet, PuLP (CBC), pandas, pdfplumber.
- **LLM:** Anthropic Claude API.
- **Фронтенд:** React 18, Vite, Tailwind CSS, React Router.
- **Безпека:** JWT, bcrypt, шифрування токенів Monobank (Fernet).

## Структура

```
app/
  api/        роутери FastAPI (auth, mono, transactions, import, debt, forecast, loans, assets, banks, advisor)
  models/     ORM-моделі
  services/   категоризація, прогноз, MILP, імпорт виписок, синхронізація, дедуплікація, радник
  core/       конфігурація і безпека
alembic/      міграції схеми БД
frontend/     React-застосунок
scripts/
  analysis/   бектести й оцінка категоризатора (лише читання БД)
  data_fixes/ скрипти дедуплікації й виправлення даних з перевіркою цілі БД
tests/        pytest проти тестової PostgreSQL
train.py      перенавчання ML-категоризатора
```

## Запуск

Потрібні Python 3.12, Node.js 18+ і Docker.

```bash
# 1. Бази даних: розробка (порт 5436) і тести (порт 5434)
docker-compose up -d db db_test

# 2. Бекенд
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # заповнити JWT_SECRET_KEY, FERNET_KEY, ANTHROPIC_API_KEY
alembic upgrade head
uvicorn app.main:app --reload   # http://localhost:8000/docs

# 3. Фронтенд
cd frontend
cp .env.example .env
npm install
npm run dev                     # http://localhost:5173
```

Команди для генерації ключів наведено в `.env.example`.

ML-категоризатор потребує навченої моделі: `python train.py` після того, як у БД з'являться категоризовані транзакції. Файли моделей зберігаються в `ml_artifacts/` і не входять у репозиторій.

## Тести

Тести працюють зі справжньою PostgreSQL, окремою від бази розробки: `tests/conftest.py` зупиняє запуск, якщо ім'я БД не закінчується на `_test`. Кожен тест ізольований SAVEPOINT і відкочується після завершення.

```bash
DATABASE_URL=postgresql://finhealifi_user:finhealifi_pass@localhost:5434/finhealifi_test alembic upgrade head
pytest
```

## Обмеження MVP

- Фонові задачі (синхронізація, планувальник) виконуються в процесі застосунку й розраховані на один воркер.
- Баланси боргів вносяться вручну; зв'язку з транзакціями погашення немає.
- Модель відсотків — прості щомісячні відсотки з постійним бюджетом на весь горизонт.
